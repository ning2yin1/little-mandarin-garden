# Little Mandarin Garden — 実装仕様

## 制作の範囲
このZIPはアプリ完成品ではなく、CodexがiPhone向けPWAを実装するための制作キットです。添付した教材を読み込んで実際に動くアプリを作ってください。教材を数問のデモに差し替えたり、プレースホルダーのまま納品したりしないでください。
アプリ名は **Little Mandarin Garden**。新規リポジトリ名の推奨は `little-mandarin-garden`。既存の指定リポジトリがある場合はそちらを使い、別ゲームのリポジトリに変更を混ぜないこと。

## 利用者と必須条件
- 個人用、日本語話者がiPhone縦画面で使用する中国語並び替え教材。アカウント・広告・課金・ランキング・体力制なし。
- 現行HSK1〜3級を目安にする72項目、各10問、合計720問を初回から全て利用可能にする。級は公式の厳密な文法所属を保証する分類ではなく、学習順の目安。
- 各文法の出題順は **日常会話4 → アニメオタク向け3 → くだらないギャグ3**。シャッフルするのはブロック。10問のジャンル順は変えない。
- タップで回答欄の末尾に追加。回答欄のブロックをタップすると戻す。長押しでブロックを持ち、回答の途中へ差し込める。既に選択済みのブロックも並べ替えられる。
- 全ブロックに声調記号付きピンインを常時表示。数字声調・カタカナ発音を使わない。
- 正解・不正解どちらの回答画面にも、正しい中国語、ピンイン、日本語訳、音声ボタン、文法解説、全ブロックの品詞と意味を表示する。
- 設定で簡体字／繁体字を切替。初期値は繁体字。途中の解答も並び順も学習記録も保持。
- 効果音あり。BGMは後から差し替え可能だが、初期状態では無音。BGM設定は実ファイル追加まで画面に出さなくてよい。
- 操作チュートリアル、使い方ページ、説明吹き出し、初回ウォークスルー、「ブロックをタップしよう」等の常設案内は不要。文法そのものの解説は必要。

## 世界観・アート
`references/target-layout.png` を画面構成の参考にする。元のSuzy's Zooのキャラクターやロゴをアプリへ転載しない。参考の柔らかい水彩、ぬいぐるみの質感、草花、ハート、淡いチェック、温かい紙色をオリジナル素材で実現する。
主人公はアプリ独自のアプリコット色のクマ。緑のチェックのマフラー、赤いハートのパッチが特徴。仲間は淡い緑のウサギと淡い紫の小鳥。`assets/characters` の完成PNGを使用し、絵文字やCSS図形で代替しない。
背景は `garden-paper.webp`。紙の中央を十分に空け、装飾は縁に置く。問題文・回答欄に花やキャラクターを重ねない。`docs/design-tokens.json` と `docs/style-guide.html` を参照。画像内に文字を焼き込まない。

## 7画面

### 1. ホーム
上部にタイトルと設定への入口。小さなクマと短い世界観コピー「ことばを並べて、今日もちいさな一歩。」、続きから、文法を選ぶ、復習の入口。情報量を抑える。続きがなければ「続きから」は表示しない。勝手に学習目標を強制しない。
下部ナビは「ホーム／文法／きろく／設定」。アクティブのみ赤くする。

### 2. 文法一覧
検索、すべて／HSK1目安／HSK2目安／HSK3目安、文法カード。カードは番号・タイトル・10問・完了状況・苦手数。全72項目を表示する。検索対象は日本語タイトル、型、説明、両字体。初期順は級→教材IDの自然順とし、表示順を変更してもIDは不変。

### 3. 文法の紹介
文法タイトル、型、説明、一例、10問を始めるボタン。例はその文法の第1問を流用できる。使い方の説明にはしない。10問完了済みでも再挑戦できる。

### 4. 並び替え問題
上部：閉じる、文法タイトル、進捗「2 / 10」、お気に入り。中央：ジャンルの小さなラベル、日本語お題、回答欄。下：未選択ブロック、やり直す、答え合わせ。
- ピンインを上、中国語を下。1ブロックはひとつの語・機能単位。例 `我／看／不／懂`、`认真／地／学习`。`喜欢` のような語は1文字ずつに壊さない。
- 並べ替え用の句読点は出題ブロックに含めない。質問の「？」は固定表示してよい。複文の読点は正解画面で表示する。ブロックは全文連続で並べる。
- 選択済みは回答欄、未選択は下の欄。元の位置に空白を残すか、穏やかな並び替えで詰めるかは統一。長押し中に未選択欄が急に縮んで位置がずれないようにする。
- 未完成でも答え合わせを押せるが、採点せず「あと○語」と短い状態だけ表示。学習ミスとして記録しない。
- タイルの文字は原則20–24px、ピンイン12–14px、操作領域44px以上。長い語は横幅を伸ばし、文字を極端に縮めない。
- 390×844を中心に、375×667、393×852、430×932等のCSSピクセルで確認。メインの問題画面は上下スクロールせず収まるよう優先的に調整。長文と文字拡大時は回答欄・ブロック欄の内部スクロールを許し、最後のブロックや採点ボタンが隠れないことを優先。

### 5. 解答・解説
同じページで穏やかに切り替えるか、下から開く解説シート。合否、全文、ピンイン、和訳、読み上げ、速度、文法説明、語句一覧、次へ。正解は小さなクマの喜ぶ絵、不正解は励ます絵。「おしい」など穏やかな表現。怒る・泣いて責める・減点演出は不要。
不正解では自分の解答も残し、正しい語順との差を示す。色だけに頼らずチェック／×も併用。正解でも解説を飛ばして自動で次へ進めない。全文表示が崩れず、解説は縦スクロール可能。
語句一覧の列：選択中字体の語／ピンイン／品詞・役割／日本語の意味。省略せず全ブロックを含める。

### 6. 10問の結果・きろく
10問中の正答数、苦手だけ復習、同じ文法をもう一度、文法一覧へ。`correctFirstTry` と最終的に正しく並べたことを分ける。途中で正解を見た問題を初見正解にしない。
記録画面に文法ごとの進捗、直近履歴、お気に入り・間違えた問題。毎日の連続日数による罰や、取り逃し感を煽る表示は不要。

### 7. 設定
繁体字／簡体字、効果音ON/OFF、効果音量、音声速度0.75／1／1.25、利用できる中国語音声の選択、記録のJSON書き出し・読み込み。BGMは将来枠として実装内部に持つ。字体は表示方式の切替であり、台湾語彙への翻訳ではない。
データ消去を置くなら確認ダイアログ必須。学習途中の設定変更後も元の問題へ戻れる。

## ブロック操作の実装契約
タップとドラッグを別経路にせず、同じ配列操作へ集約する。状態は `bankTokenIds` と `answerTokenIds`、移動中の `dragTokenId`。各トークンIDは一つの欄に一回だけ存在する。
長押しは約300ms、移動しきい値8px程度。開始前の縦移動はリストスクロールを優先。開始後は `setPointerCapture` を使い、浮いて見えるプレビューと挿入位置の線を表示。指の下でも位置が見えるようプレビューを少し上にずらす。
折り返した回答欄でも、指に近い行・ブロックの前後を座標から決める。末尾だけでなく先頭・行末・行頭にも挿入可能。回答内の移動では元の位置を取り除いた後の挿入indexへ調整する。
`pointercancel`、画面切替、アプリが背景に回った場合は安全に元へ戻す。ドロップ後に合成clickでさらに追加・削除しない。外へ落としたら破棄せず元へ戻す。タップしている途中で字体切替が入ってもトークンIDを変えない。
HTML5 native drag-and-dropだけに依存しない。Pointer EventsまたはiOS対応が確認できるソート実装を使う。操作ブロックだけ `touch-action: none` にできるが、文法一覧や解説までスクロール禁止にしない。
ドラッグの代替として、回答欄をタップして挿入位置を選び、その後未選択の語をタップして挿入できるとよい。UIは細いキャレットで表し、長い操作説明は加えない。VoiceOverでは「左へ／右へ／回答に追加／戻す」の操作を利用できるようにする。

## 採点
外部AI・ネットAPIを使わずローカルで判定する。入力順の `tokens[].simplified` を連結し、正解候補を同じ方法で連結して比較。重複語のトークンIDが入れ替わっても同じ文なら正解とする。空白・句読点・字体の違いを誤答要因にしない。使用できる語の多重集合は必ず一致させる。
`accepted_orders` は模範順とよくある別解を持つ。時間を主語より前に出す等の自然な語順は収録済み。中国語の全ての別解を網羅した汎用文法判定器ではない。納品前に各文法で妥当な別解を検討し、追加時は理由とテストを残す。語を勝手に補った解答や意味が逆転する語順を「似ている」だけで許容しない。
例「我明天去学校」「明天我去学校」は両方正解。「我喜欢他」と「他喜欢我」は別の意味なので同一扱いにしない。添付fixturesを通す。
初期シャッフルが正解と同じ表記順なら再シャッフルする。同じ語が複数ある場合も表記で確認し、重複IDの出現・消失を防ぐ。

## ピンイン・字体
`data/curriculum.json` の値をそのまま使い、ブラウザの自動変換に依存しない。文字の切替は `simplified`／`traditional` の表示フィールドを選ぶだけ。問題ID、トークンID、採点キーは不変。
一・不には基本的な文脈変調を反映。一部の軽声を反映し、第三声同士の変調は辞書表記を保つ。儿化は `nǎr / zhèr / diǎnr` のように記す。一般的な普通話の教材で、繁体字でも自動的に台湾の地域発音へ変更しない。
品詞・意味は学習用の簡潔な説明。可能補語の「不」など、文中の働きがあるものを優先して表示。語を一文字ずつに機械分解しない。

## 音声・効果音
全文の読み上げはiPhoneの `speechSynthesis` と中国語音声を使う。録音データ720件や有料APIは不要。ボタン操作時だけ再生し、前の再生を `cancel()` してから新しい発話を行う。画面遷移・停止ボタン・バックグラウンド化でも止める。`voiceschanged` に対応し、初回の空リストを恒久的な「非対応」と判定しない。
繁体字にも共通の普通話音声を初期候補とする。音声選択では見つかった中国語音声を表示し、zh-TWも選べるようにする。字体の切替で保存済みの音声選択を勝手に変更しない。ピンインは音声合成に読ませず漢字全文のみを読む。
中国語音声が存在しない場合は「中国語の音声が見つかりません」と短く表示し、読み上げ成功を装わない。iOSの音声の導入状況によってオフライン読み上げの利用可否は異なる。アプリ本体のオフライン動作とは分けて確認する。
`assets/audio` の短いオリジナルWAVを使用。tap、remove、insert、correct、incorrect、completeをマッピング。ドラッグの移動毎に連打しない。初回タップでAudioContextを起動・復帰。音量初期値は控えめに。音声中は効果音を抑える。サイレントモードでの挙動を実機確認し、再生できない場合も学習を妨げない。
BGMは `bgm-slot.json` の後付け枠。初期ロードで存在しない音声URLをfetchしない。追加時にはユーザー操作による再生開始、ON/OFF・音量・ループ・バックグラウンド停止を実装する。

## 保存・拡張
IndexedDB等の端末内保存。初回起動で全員の記録を生成する必要はない。保存するもの：字体、音声・効果音設定、現在の問題と並び順、問題ID別の初回正答・試行回数・最終学習日・お気に入り・復習状況、文法ごとの履歴。
保存に失敗したときは進捗が保存されていないことを短く通知し、ゲーム自体は続けられるようにする。自動で記録を消さない。プライベートブラウズやサイトデータ削除では消える場合があるためJSONバックアップを用意する。
JSON取り込みは構造とバージョン・IDを検証し、壊れたファイルを適用しない。未知の将来IDは保留または安全に無視し、既存記録を破壊しない。
HSK4〜6追加を想定し、レベルは1〜6を許容。今は4〜6の空ページを出さない。学習IDを配列indexで代用しない。`schema_version` と `content_version` を分け、教材更新時も既存IDを維持する。

## PWA・iPhone
`index.html` を入口とし、manifest、service worker、アイコンを用意。`display: standalone`、`theme_color`、`background_color` を設定。180pxのApple touch icon、192/512pxの通常アイコンを同梱済み。maskableを宣言する場合は中央セーフエリアを別途確認したアイコンを作ること。提供画像を検証せずmaskable指定しない。
`viewport-fit=cover`、safe-area-insetの上下左右、100dvh（必要なら100svhフォールバック）を扱う。Safariのアドレスバー伸縮、ホームインジケーター、文字拡大でもボタンが隠れないようにする。
ダブルタップズームは操作要素の `touch-action: manipulation`、ドラッグ中の局所処理で抑える。`user-scalable=no` や `maximum-scale=1` でページ全体の拡大を一律禁止しない。入力欄は16px以上でフォーカス時の自動拡大を避ける。
初回オンライン読み込み後は問題・画像・効果音・画面遷移をオフラインで利用可能に。ローカルフォントスタックを使い、Google Fonts等を必須にしない。HSK4〜6追加は教材ファイルを分割し遅延ロードできる構成。
GitHub Pagesのサブディレクトリ `/little-mandarin-garden/` で動く相対パスまたは適切なbase設定。service workerのscope/start_urlも合わせる。外部ルーティングが404になる構成を避け、ハッシュルーティングかローカル状態を使う。
更新はHTML/JS/教材の世代が混ざらない設計。新キャッシュを完成してから切替え、学習中に強制リロードせず「更新する」等の短い操作で次の安全なタイミングに適用する。記録はキャッシュ削除と独立。キャッシュのバージョン変更で学習記録を消さない。
この制作キット自身はGitHubへアップロード・デプロイしていない。実装後のURLは、使用リポジトリと公開設定から確認して報告すること。推測URLを完成済みとして提示しない。

## 完了条件
`ACCEPTANCE_CHECKLIST.md` と `data/acceptance-fixtures.json` を確認。実装した変更と、実際に通した検証、実機未確認事項を区別して報告。デザインだけのスクリーンショットで機能完成としない。利用者に追加の画像生成や例文作成を投げ返さず、提供済み素材と720問を使って仕上げる。
